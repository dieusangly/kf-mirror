# Repository migration plan

**Approved migration sequence.** Migrate one implementation boundary at a time inside the existing `knowledge_foundry` namespace. Retain the checkout launchers, deployed data locations, schema files and current v1 replay environment. Start with the compatibility checks and shared utilities. Leave the raw-document Reasoning Foundry as a separately testable future capability.

The [architecture](architecture.md) describes the dependencies that motivate this order. The [file map](file-migration-map.md) assigns every tracked path a destination. The [baseline](regression-baseline.md) supplies reproduction commands, denominators and known gaps. Steps 1–7 have implementation records in the [progress report](repository-migration-progress.md). Stage A3 owns independent acceptance. Step 8 belongs to B1.

## Compatibility decisions

| Contract | Failure mode on a path-only refactor | Migration rule |
| --- | --- | --- |
| Python imports and discovery | `PYTHONPATH=src:tests`, root-relative `scripts.*`, bare sibling imports, in-function imports and `Path(__file__).parents[n]` resolve differently after a move. A star re-export can lose private names, create distinct class identities or cause monkeypatches to miss the executing module. | Keep the old import paths while moving consumers. Exercise old/new imports in fresh interpreters, including documented `-m` entrypoints, test doubles, provider factories and import-time defaults. Resolve data roots explicitly before changing nesting depth. |
| CLI and workflow | A working function import does not preserve `python -I scripts/…`, argparse choices, output JSON, exit codes, resume checkpoints or the stage DAG. `validate_artifact_examples.py` takes positional paths and runs examples by default. | Keep checkout launchers. Compare representative successful and failing invocations, help, command aliases, exclusive outputs, status reports and side effects. Keep `--allow-paid` and explicit publication semantics. [Documented CLI tests](../tests/test_documented_commands.py) |
| Three app launch surfaces | Moving a Streamlit file can break sibling imports or CSS. Moving the contributor server can change its database default, authentication cookie or static-asset root. Opening the KPG template omits generated data and scripts. | Keep the real launch paths, URL/query parameters, default ports and asset names. Test direct and automatic Assistant modes, HTTP endpoints and generated standalone graphs. [Entrypoints](architecture.md#entrypoints-and-startup) |
| Artifacts, prompts and checkpoints | Relative paths, absolute workflow paths, file names and byte hashes participate in lineage. A moved prompt, changed cluster request or reordered JSON can change a build ID or cause reuse of incompatible results. | Keep resources and saved runs at existing paths. Introduce a root resolver for new code. Compare bytes where a digest applies, and compare normalized results only for fields explicitly volatile, such as replay latency or fresh output locations. |
| Schemas and identifiers | Equal-looking records can produce different IDs if Unicode escaping, separators, ordering, newline delimiters, span offsets or digest inputs change. SQL search projections depend on original chunk membership and context. | Preserve schema filenames, versions, references and validation behavior. Test old bundles and compare IDs, revisions, evidence spans, proofs, projections and graph edges. Keep byte hashing, canonical JSON hashing and newline-joined string hashing distinct. |
| Accepted code and datasets | A wrapper at an executable's former path changes its SHA. The registry rejects an alternate engine path even for identical bytes. Changing an indirectly pinned source breaks offline evaluation validation. | Keep v1 executable and evaluation sources byte-for-byte at their recorded paths. Add an adapter outside the frozen files. Use a successor manifest, versioned implementation and fresh review if a future change intentionally updates identity. |
| PostgreSQL and contributor SQLite | A missing SQL resource can leave a new DB without tables. Editing existing SQL trips its stored checksum. Starting the contributor app against an empty default file can look like data loss. | Package lookup and historical filenames/checksums must agree. Use an isolated DB and a backup copy of the SQLite store to test compatibility. Keep user accounts, sessions, attachments, ownership, history and the existing default path. |
| Historical tests and evaluations | A different checkout path or a new Python file can invalidate a saved run identity even with unchanged answers. Updating old expected values would hide a regression. | Keep immutable runs, references, fixtures and review decisions. Validate the active baseline under its original pins. Give migrated executions fresh output directories and identities. Record intended changes and compare metrics on the same cases. |

## Migration steps and acceptance

Each step can ship independently once its prerequisites and checks pass. Keep tests and fixtures at the paths in the ledger. For a behavior-preserving move, any new failure, new skip, changed pin or unexplained output difference stops cutover. If a service or artifact needed for a step is unavailable, record the specific check as pending. Re-run that gate with the prerequisite available before marking the step complete.

### 1. Protect compatibility and resource lookup

Capture the A1 revision, the local artifact inventory, active manifests and all registry pins as test inputs. Establish root/resource lookup for new code, with explicit handling of repository-relative, run-relative and output paths. Initially retain `config/`, `schemas/`, `data/`, `examples/`, `src/knowledge_foundry/prompts/`, SQL migrations and app assets at their current locations. Preserve the current default behavior of `KF_ASSISTANT_CONFIG`, `KF_DATABASE_URL` and the API-key configuration.

**Accept when** the current commands run from the documented checkout, the 24 currently isolated launchers still pass with `-I`, the frozen formalizer still runs by direct invocation, and package imports find their resources in a fresh interpreter. Recheck all receipt pins and pass the full integrated baseline and replay. Demonstrate that a changed byte or mismatched path fails validation. Compare a prior workflow identity on its original checkout with a fresh run at the new revision and confirm that cross-revision resume detects the change.

### 2. Extract shared services and provenance primitives

Move concurrency, embeddings, generic request token counting and model transport into `shared/`. Extract vector normalization from semantic clustering and canonical JSON hashing from structural links. Move evidence-key and cross-record bundle validation to `provenance/`. Keep fixture-manifest checks in the example CLI. Expose existing names, including the historical `structural_chunks.stable_hash` import, through compatible modules. Port consumers before removing any private coupling.

**Accept when** both example bundles validate, IDs/revisions and cache keys match for Unicode, ordered evidence and spanless headings, and equivalent serial/concurrent jobs produce equal ordered results. Exercise embedding/request-count cache hits, duplicate work, retry/failure behavior, token bounds and cancellation on a worker error. Import shared helpers and source identity primitives without constructing a provider, registry or database. [Concurrency checks](../tests/test_pipeline_concurrency.py) · [Request counter checks](../tests/test_request_counter_concurrency.py)

### 3. Move Knowledge Engineering in pipeline order

Move ingestion and corpus scope first. Extract provider types/config and chunk-text helpers before moving parsing, providers, freezing and reviews. Next split the generation-request contract from claim execution and the saved-classification reader from review. Then move semantic preparation, claims/classification and summaries. Retain the configured `knowledge_foundry.unstructured_provider:Provider` alias and preserve fixture-vs-reviewed acceptance checks. Keep the 25 script names and old module entrypoints callable.

**Accept when** each producer's saved result still loads in its pre-move consumer. Exercise fixture ingestion → parsing → reviewed chunks → clustering → both generation branches through the command launchers. Revalidate both retained structuring runs against the measured counts and existing acceptance flags. Compare fixture artifacts, candidate IDs, topic memberships, summary ancestry, completeness reports and retry/resume behavior. Verify provider-native replay, negative review/lineage controls and the first three import cycles identified in the [audit](architecture.md#coupling-found-in-the-checkout).

### 4. Expose a checked Reasoning Engine interface

Introduce `reasoning_engine/runtime.py` with configuration/encoding/query validation, solve and result checking. For the supported v1 packages, let that boundary call the verified historical implementation. Keep the engine, formalizer, schema and accepted datasets in place. Isolate the replay and pilot orchestration interfaces from future document authoring. Separate receipt, selection and passage verification into a reader usable by both the Assistant and Contributors. Preserve the v1 Assistant dataset module at its pinned path.

**Accept when** the unchanged historical replay **and** the new package interface run the same saved queries for 192 synthetic, 18 BO and 32 KYC versions. Compare full result records and valid certificates across both entrypoints. Test wrong bytes, status/receipt disagreement, invalid proofs and a mismatched engine path. Confirm fresh-case execution uses only the selected policy, new facts and query. The engine must run with no model, DB, engineering artifacts or Assistant import. [Replay contract](../scripts/replay_reasoning_pilot.py) · [Engine tests](../tests/test_aml_cft_reasoning.py)

### 5. Isolate Retrieval, storage and graph projection

Keep `retrieval/` and `storage/` as public packages. Put engineering bundle ingestion behind `retrieval/adapters/engineering.py`. Decouple online answering from offline preparation readers. Keep search scoring and transactional queries in their current store until tests establish equivalence. Move graph data construction and graph binding to Provenance, and HTML assembly to the KPG application. Preserve the two numbered migration files exactly.

**Accept when** duplicate imports return the same snapshot ID, failed imports roll back, explicit publication and corpus isolation work, and existing sessions/history/feedback resolve to the same snapshot and owner. Compare fixture keyword/vector/combined results, all four modes, original-span resolution, citations and insufficient-evidence behavior. Run real PostgreSQL/pgvector tests and the documented end-to-end fixture command test. Render both example graphs, compare node/edge identities and exercise the legacy standalone and managed graph path checks. Migrate a restored test copy twice and verify ledger checksums. [Storage tests](../tests/storage/) · [Retrieval tests](../tests/retrieval/) · [Graph tests](../tests/test_render_knowledge_graph.py)

### 6. Separate Assistant and application wiring

Keep `Assistant.ask` and `DocumentAssistant` request/return behavior. Move AML policy projection out of generic receipt parsing, retaining BO/KYC applicability, synthetic-source labeling and quoted-user-fact validation. Migrate the three presentations independently. Extract contributor account/session and contribution persistence into `storage/`, keep HTTP, submission policy and catalogue presentation in `applications/contributors/`. A pinned v1 module may continue using its original implementation until a versioned successor is ready.

**Accept when** both Assistant modes start through the existing Streamlit file, including without a published DB. Check routing, local-only handling, proof display, original citations, session reset, saved chat token and bounded diagnostics. Validate 007 preparation, reproduce all 288 question identities and 192 provisional engine references, and pass the seven-case mocked runtime smoke. Launch Contributors against a disposable copy with existing and pre-account rows. Check account login/logout, cookies and public origin, ownership, downloads, transitions and active/history views. Confirm 121 bilingual cases and 26 sources in the default catalogue. Open a generated KPG offline and inspect filtering, navigation and source detail. [UI tests](../tests/test_reasoning_assistant_ui.py) · [Contributor coverage](../tests/test_contributors_auth.py) · [Viewer tests](../tests/test_kpg_viewer.py)

### 7. Cut over orchestration and version future evaluation tools

Move the document workflow and reporting to `workflows/`, with the old script invoking the new service. Preserve stage names, review prompts, paths, locking, dependency invalidation, attempt budgets and explicit publication. Reconcile filename-based invalidation with the new paths. Keep historical assistant generator/validator files intact. Introduce shared preparation logic and one-way imports in a separately versioned successor when changing that workflow. Retire an old import only after inspecting scripts, tests, configs, receipts, external provider strings and supported historical invocations.

**Accept when** offline fixture workflows can start, stop, resume with identical inputs and reject stale inputs. Exercise interrupted/partial runs, report totals, concurrent locks, review failure and publication refusal. Verify old status/history can be inspected with the matching runtime, and the new controller creates fresh execution identity. Repeat the integrated suite and accepted replays on the migrated entrypoints. Compare migrated evaluation runs on the original denominator and keep the recorded historical live verdict intact. [Workflow tests](../tests/test_workflow.py) · [Evaluation protocol](aml-cft-reasoning-assistant-evaluation.md)

### 8. Reasoning Foundry independence

Reserve `reasoning_foundry/` for a later feature. Its first vertical test should take a raw PDF or HTML document, source/edition metadata and its own configuration. Record the original digest, extract a locatable passage, build a source-linked clause/rule, validate an encoding and separate query, then execute and check a proof through the Engine. Review/acceptance of newly authored rules is a separate action. The older pilot's selected claims and curated mappings remain available to reproduce its history.

**Accept when** an isolated raw-only workspace can complete that test with no `knowledge_engineering` import, fixture bundle, ingestion snapshot, accepted chunks, clusters, claims, index, graph, DB or prebuilt reasoning dataset. Reopen the original and resolve each cited passage. Reject a changed original or unresolvable locator. Run the same inputs twice and compare identities, rules and checked result, controlling any authoring provider through a fixture. Any optional engineering enrichment must be opt-in and exercised separately.

## Rollback and decision points

Use one reversible change set per step. Run the legacy and new entrypoints against copies of the same frozen inputs before switching callers. If a gate fails, return callers to the preceding implementation and preserve the failed candidate outputs in their fresh run. Keep the last working checkout with its resource tree and pinned artifact set available. For storage changes, rehearse recovery on a verified backup copy before any deployment decision. The package migration requires no schema rewrite or production data conversion.

A separate decision is needed to change an accepted executable/schema, adopt an installed distribution outside a checkout, retire an externally used import, or promote a new evaluation or raw-document ruleset. None is a prerequisite for the first shared-service extraction.
