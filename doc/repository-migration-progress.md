Checkout defaults are anchored to the source tree. Workflow state and stage locations are relative to their run directory. User-supplied relative config and output paths keep each CLI's existing working-directory semantics, including exclusive creation for replay output. `KF_ASSISTANT_CONFIG`, `KF_DATABASE_URL`, and `OPENAI_API_KEY` retain their defaults and precedence.

Retrieval and Workflow own their existing `ROOT` aliases. Retire either only after checking its users in scripts, tests, configs, pinned modules and supported external imports and obtaining review of the compatibility change. The maintainers of the v1 receipts and preparation own the frozen paths and their loaders for the lifetime of those versioned contracts. The resolver targets the existing source layout, as planned. A separately approved installed distribution would need its own resource strategy. There are no architectural deviations.
